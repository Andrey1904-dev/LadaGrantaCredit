# LADA Кредит & Гараж

Мобильное веб-приложение (Mobile-First SPA) для владельцев **LADA Granta**:
учёт расходов и ТО, аналитика стоимости владения и умное управление автокредитом.
Оформление — в эстетике **Granta Sport**: тёмная графитовая палитра, красный
акцент `#E33337`, Manrope + Oswald. Неофициальный концепт, не сервис АО «АВТОВАЗ».

![stack](https://img.shields.io/badge/React%2019-Vite%207-61dafb) ![styles](https://img.shields.io/badge/Tailwind%20CSS-4-38bdf8) ![backend](https://img.shields.io/badge/Supabase-PostgreSQL%20%2B%20Auth-3fcf8e)

## Функционал

| Экран | Возможности |
|---|---|
| **Авторизация** | Вход / регистрация по email и паролю (Supabase Auth), повторная отправка письма подтверждения с анти-спам-кулдауном, **демо-режим одной кнопкой в любой сборке** (в том числе на GitHub Pages с ключами) |
| **Главная** | Виджет авто (номер, пробег с обновлением), переключатель ракурса «Гараж / На трассе», карточки «Ближайшее ТО», «Средний расход л/100 км» и «Пробег в месяц», **календарь владельца «Ближайшие события»** (платёж, ОСАГО, техосмотр, права, налог, переобувка — с обратным отсчётом), виджет кредита, быстрые действия добавления расхода, сводка трат за месяц |
| **Кредит → Мой график** | Остаток долга по аннуитетной формуле от числа внесённых платежей (`loans` + `transactions`), прогресс-бар, отметка платежа, история |
| **Кредит → Досрочное погашение** | Разовый взнос и/или ежемесячная переплата, два сценария — **сократить срок** или **уменьшить платёж**; считает экономию на процентах, новый срок и новый платёж, сравнивает оба варианта и подсказывает выгодный |
| **Кредит → Моделирование** | Подбор кредита: 4 поля (сумма, ставка, платёж, срок) — заполняете любые 3, четвёртое считается автоматически (ставка — численно, бисекцией). Калькулятор ПДН со шкалой 0–100% (зелёная <30%, жёлтая 30–50%, красная >50%) |
| **Расходы** | Сумма трат, стоимость километра, **топливная аналитика** (расход л/100 км, ₽/км, запас хода на баке), **график расходов по месяцам** (столбики + скользящее среднее), **стоимость владения** (₽/мес, ₽/км, сравнение с отраслевым ориентиром) и **прогноз на 12 месяцев** (кредит + топливо + ТО + ОСАГО + налог), Donut-диаграмма по категориям, фильтр, лента операций, **редактирование** операции |
| **ТО** | Автоматический план обслуживания по пробегу и мотору: регламент завода ⇄ практика форумов, срочность каждой работы, прогноз «когда» по вашему пробегу, бюджет ближайших работ, карта ТО-1…ТО-8, «болячки» Гранты по пробегу, сезонные чек-листы, напоминания (ОСАГО, диагностическая карта, **водительские права**, сезон шин), **расчёт транспортного налога** по мощности и региону, отметка «сделано» одной кнопкой |
| **Моя Гранта** | Редактирование данных авто (номер, VIN, пробег, начальный пробег), выбор «исполнения кузова» (чёрный / белый, визуальное демо), напоминание об ОСАГО (индикатор при <14 дней), журнал ТО и ремонтов, **экспорт данных**: резервная копия JSON и выгрузка расходов/журнала ТО в CSV для Excel |

### Подключение Supabase

Проект уже подключён к Supabase (`.env` содержит `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY`; файл не коммитится).

**Осталось применить схему БД (одно действие, ~1 минута):**

1. Откройте [Supabase Dashboard](https://supabase.com/dashboard/project/dcgurmwvpgzmlfivxoso/sql/new)
   → **SQL Editor** → New query.
2. Вставьте содержимое [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. Готово: таблицы `profiles`, `cars`, `loans`, `transactions`, `maintenance`
   с RLS-политиками и триггером профиля созданы. Приложение подхватит их
   автоматически (в шапке есть кнопка «Повторить»).

> ⚠️ DDL нельзя выполнить через publishable-ключ — только владелец проекта
> в Dashboard (или через `psql`/Management API). Publishable/anon-ключи
> по задумке Supabase имеют доступ только к данным, не к схеме.

**Email-подтверждение:** см. отдельный раздел
[«Регистрация: письма, лимиты и почта .ru»](#регистрация-письма-лимиты-и-почта-ru) —
там же лечение ошибки `email rate limit exceeded`.

### Демо-режим

Демо — это **переключатель во время работы приложения**, а не режим сборки:

| Ситуация | Что происходит |
|---|---|
| Ключей Supabase нет | Демо включён принудительно, вход по email скрыт |
| Ключи есть (в т. ч. на GitHub Pages) | Кнопка «Войти в демо-режим» на экране входа переключает приложение на локальный бэкенд и открывает заполненный кабинет |
| Выход из аккаунта | Флаг демо снимается, приложение возвращается в облачный режим |

Данные демо (автомобиль, кредит, ~50 расходов за год, журнал ТО) создаются
детерминированным сидом в [`src/lib/local.ts`](src/lib/local.ts) и лежат только
в `localStorage` этого браузера. В шапке есть кнопка **«Сбросить демо»** —
пересоздаёт набор данных.

> Раньше кнопка демо вызывала `signIn('demo@lada.ru')` **у Supabase**: в сборке
> с ключами (то есть на опубликованном сайте) запрос падал с «Invalid login
> credentials», ошибка глоталась `void enterDemo()`, и по нажатию не
> происходило ничего. Теперь демо-бэкенд подменяется на лету
> ([`src/lib/index.ts`](src/lib/index.ts)), а ошибки показываются на экране.
> Сценарий закреплён тестом `node scripts/smoke-demo.mjs` (входит в `npm run smoke`).

Типы схемы БД лежат в `src/types/database.types.ts` (формат `supabase gen types typescript`).

## Регистрация: письма, лимиты и почта .ru

### Симптом

При регистрации вместо аккаунта появляется ошибка:

```
email rate limit exceeded
```

…а завести аккаунт на `@mail.ru`, `@yandex.ru`, `@bk.ru` не получается вовсе.

### Причина

Ошибка приходит от Supabase, а не от приложения. Пока в проекте **включено
подтверждение email**, каждая регистрация = отправка письма, а письма шлёт
**встроенный отправитель Supabase**, у которого два жёстких ограничения
([документация Supabase](https://supabase.com/docs/guides/auth/rate-limits)):

| Ограничение встроенного отправителя | Что видит пользователь |
|---|---|
| **2 письма в час на весь проект** | `email rate limit exceeded` (429, `over_email_send_rate_limit`) |
| Письма только на адреса **участников команды** проекта | `Email address not authorized` — то есть чужой ящик (в том числе любой `.ru`) зарегистрировать нельзя |

Поднять лимит на тарифе Pro нельзя — он одинаковый на всех планах.
То есть «регистрация на .ru» ломается не из-за домена, а из-за того, что
письмо такому адресу встроенный отправитель просто не доставляет.

### Решение A — быстро: регистрация без писем (30 секунд)

Подтверждение email выключается, аккаунт создаётся мгновенно на **любой**
адрес — mail.ru, yandex.ru, bk.ru, list.ru, gmail.com, .рф.

Вариант 1 — Dashboard:
**Authentication → Sign In / Up → Email → выключить «Confirm email»**.

Вариант 2 — одной командой из репозитория:

```bash
# токен: https://supabase.com/dashboard/account/tokens (строка sbp_…)
SUPABASE_ACCESS_TOKEN=sbp_xxx npm run supabase:auth -- --no-confirm
```

Скрипт [`scripts/supabase-auth-setup.mjs`](scripts/supabase-auth-setup.mjs)
выключает `mailer_autoconfirm` **и** разрешает вход тем, кто уже
зарегистрировался, но письма так и не дождался
(`mailer_allow_unverified_email_sign_ins`) — иначе такие аккаунты остаются
заблокированными навсегда.

Проверить текущее состояние проекта (без изменений):

```bash
SUPABASE_ACCESS_TOKEN=sbp_xxx npm run supabase:auth
```

### Решение B — правильно: свой SMTP (письма остаются)

Свой SMTP снимает оба ограничения: письма уходят на любые адреса, лимит
поднимается до настраиваемого значения. Подойдёт Resend, Brevo, Unisender,
Postmark, AWS SES; для надёжной доставки в mail.ru/yandex.ru удобны
российские отправители (Unisender, Sendpulse) или Яндекс 360.

```bash
SUPABASE_ACCESS_TOKEN=sbp_xxx npm run supabase:auth -- --smtp \
  --smtp-host smtp.resend.com --smtp-port 465 \
  --smtp-user resend --smtp-pass re_xxx \
  --smtp-from no-reply@ваш-домен.ru --smtp-name "LADA Кредит" \
  --rate-limit 100
```

И укажите, куда вести ссылки из писем (иначе подтверждение уводит на
`localhost`):

```bash
SUPABASE_ACCESS_TOKEN=sbp_xxx npm run supabase:auth -- \
  --site-url https://andrey1904-dev.github.io/LadaGrantaCredit/
```

> Не забудьте про SPF/DKIM для домена отправителя — без них письма
> уезжают в «Спам» именно у mail.ru и yandex.ru.

### Что делает само приложение

Код не может изменить настройки чужого проекта, но делает всё остальное,
чтобы регистрация не ломалась на пустом месте:

- **любая почта принимается** — валидация не ограничивает доменные зоны:
  `.ru`, `.рф` (переводится в punycode), `.com`, `.by`, `.kz`;
- **чинит ввод** — лишние пробелы, `mailto:`, Caps Lock, запятая вместо точки,
  русская раскладка (`ivan@mаil.ru` с кириллической «а», `ivan@майл.ру`
  → `ivan@mail.ru`), подсказывает опечатки (`mail.ry` → `mail.ru`);
- **не тратит лимит писем** — локальный таймер 60 секунд между попытками
  (Supabase всё равно откажет) и понятный отсчёт на экране;
- **объясняет ошибку по-русски** вместо `email rate limit exceeded`, сразу
  показывая, что нужно сделать владельцу проекта;
- **не даёт застрять** — кнопки «Попробовать войти» (аккаунт мог создаться,
  даже если письмо не ушло) и «Отправить письмо ещё раз», ссылка на веб-почту;
- **предупреждает заранее** — если в проекте включено подтверждение email,
  на экране регистрации висит предупреждение (приложение узнаёт это через
  `GET /auth/v1/settings`);
- **не предлагает example.com** — тестовые домены Supabase отклоняет
  (`email_address_invalid`), поэтому подсказка в поле теперь `ivan@mail.ru`.

## Деплой на GitHub Pages

1. В настройках репозитория: **Settings → Pages → Source = GitHub Actions**.
2. Добавьте секрет `VITE_SUPABASE_ANON_KEY` в
   **Settings → Secrets and variables → Actions → вкладка Secrets → New repository secret**:
   - Name: `VITE_SUPABASE_ANON_KEY`
   - Secret: publishable (anon) ключ проекта —
     Supabase Dashboard → Project Settings → API → Project API keys → `anon` / `publishable`
     (длинная строка, начинается с `eyJ…`)

   `VITE_SUPABASE_URL` задавать не обязательно: если секрета нет, workflow
   использует адрес проекта по умолчанию (`https://dcgurmwvpgzmlfivxoso.supabase.co`,
   он публичный). Хотите переопределить — создайте секрет/variable `VITE_SUPABASE_URL`;
   anon-ключ тоже можно положить во вкладку **Variables** — workflow смотрит оба места.

   > ⚠️ Именно **New repository secret** в разделе «Secrets and variables».
   > Раздел **Settings → Environments** — это другое: секреты внутри окружений
   > не появляются в списке секретов и **не видны job'у сборки**, из-за чего
   > деплой уйдёт в демо-режим (или упадёт на проверке ключей).

   Без ключей деплой **упадёт с понятной ошибкой** (шаг «Проверить ключи Supabase»),
   чтобы на Pages не опубликовалась сборка без работающей регистрации.
3. Запушьте в `main` — workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
   соберёт `dist` (с `base: '/LadaGrantaCredit/'`) и опубликует на Pages.

## Раздел «ТО»: откуда берутся данные

Ничего заполнять руками не нужно. Достаточно текущего пробега — план
обслуживания собирается автоматически из базы знаний
[`src/lib/service.ts`](src/lib/service.ts) (25 регламентных работ — часть
зависит от мотора, 10 типовых «болячек», 2 сезонных чек-листа). Журнал ТО из вкладки «Моя Гранта» только уточняет план:
записи распознаются по ключевым словам, и работа получает реальную дату и пробег
последнего выполнения. Если записи нет — последнее выполнение оценивается по
пробегу (`estimated`, в интерфейсе помечено как «оценка по пробегу»).

### Два режима интервалов

Переключатель вверху экрана меняет всю математику:

| Работа | Регламент завода | Практика форумов |
|---|---|---|
| Моторное масло + масляный фильтр | 15 000 км / 12 мес | **8 000 км** / 12 мес |
| Салонный фильтр | 15 000 км / 12 мес | 10 000 км / 6 мес |
| Воздушный фильтр | 30 000 км | 15 000 км |
| Свечи зажигания | 30 000 км | 20 000 км |
| Топливный фильтр | 30 000 км | 20 000 км |
| Тормозная жидкость DOT-4 | 45 000 км / 3 года | 45 000 км / **2 года** |
| Антифриз G12 | 75 000 км / 5 лет | 60 000 км / 4 года |
| Ремень ГРМ с роликами | 75 000 км / 5 лет | **60 000 км** (комплектом с помпой) |
| Масло МКПП (3,1 л) | 75 000 км | 60 000 км |
| Регулировка клапанов (8V) | 90 000 км | 45 000 км |
| Ремень генератора | 90 000 км | 45 000 км |
| Развал-схождение | 30 000 км | 15 000 км / сезон |
| Сезонная смена шин, АКБ, антикор, техосмотр | по календарю | по календарю |

Срочность считается как `прогресс = пройдено / интервал` по пробегу **и** по
времени — берётся то, что наступает раньше: `ok` → `soon` (≥ 80 %) → `due`
(≥ 95 %) → `overdue` (> 100 %). Прогноз «когда» переводит остаток километров в
дни по вашему среднему пробегу за месяц (из истории заправок и обновлений
одометра).

### Что ещё есть на экране

- **Бюджет ближайших работ** — вилка стоимости по позициям, которые уже
  просрочены или подойдут в ближайшие 5 000 км.
- **Карта ТО** — что именно делают на ТО-1 … ТО-8 (кратно 15 000 км) с учётом
  выбранного мотора.
- **«Болячки» Гранты** — типовые отказы с диапазонами пробега из отзывов
  владельцев (помпа 15–60 тыс., задние ступичные от 12 тыс., стойки
  стабилизатора 20–40 тыс., коррозия арок с 1–3 года и т. д.); те, что попадают
  в ваш пробег, подсвечиваются.
- **Сезонные чек-листы** — подготовка к зиме и к лету.
- **Напоминания** — ОСАГО, диагностическая карта, сезон шин; сроки хранятся

- **Кнопка «Сделал»** — создаёт запись в журнале ТО (`maintenance`) с текущим

## Формулы (аннуитет)

- Платёж: `P = S·r·(1+r)^n / ((1+r)^n − 1)`
- Срок: `n = ln(P / (P − S·r)) / ln(1+r)`
- Остаток после k платежей: `B(k) = S·(1+r)^k − P·((1+r)^k − 1)/r`

где `r = ставка/12/100` — месячная ставка.

## Формулы (топливо и ТО)

- Расход считается по отрезкам между соседними заправками с одометром
  («от полного до полного»): `л/100 = 100 · литры / (одометр_текущий − одометр_предыдущий)`,
  где `литры = сумма чека / цена литра` из настроек (литры в БД не хранятся).
  Средний расход — среднее по отрезкам; отрезки короче 50 км, длиннее 2 000 км
  и значения вне 3–25 л/100 отбрасываются как шум.
- Стоимость километра: `Σ всех расходов / (текущий пробег − начальный пробег)`.
- Пробег в месяц: `(Δ одометра / Δ дней) · 30,4` по чекам с пробегом
  (нужно минимум 20 дней истории, иначе прогноз по датам не показывается).
- Срочность работы ТО: `progress = max(пройдено_км / интервал_км, прошло_мес / интервал_мес)`.

## Досрочное погашение

Вкладка «Кредит → Досрочка» моделирует два законных сценария (ст. 809–810 ГК РФ,
заявление в банк подаётся к дате очередного платежа):

| Сценарий | Что меняется | Когда выбирать |
|---|---|---|
| **Сократить срок** | платёж прежний, кредит заканчивается раньше | почти всегда выгоднее: проценты начисляются на остаток, и вы убираете «хвост» дорогих месяцев |
| **Уменьшить платёж** | срок прежний, ежемесячный взнос пересчитывается аннуитетом | когда нужно снизить нагрузку на бюджет (тот же ПДН) |

Считает [`simulatePrepayment`](src/utils/loan.ts): помесячная симуляция остатка —
разовый взнос списывается до первого платежа, ежемесячная переплата добавляется
к каждому взносу. Экономия = разница процентов с базовым графиком без досрочек.
Расчёт покрыт тестами (`npm test`): например, 1 000 000 ₽ под 12 % на 12 месяцев
и взнос 500 000 ₽ — 17 254 ₽ процентов и 6 месяцев при сокращении срока против
33 093 ₽ и 12 месяцев при уменьшении платежа.

## Стоимость владения и прогноз

На вкладке «Расходы» считаются три вещи ([`src/utils/stats.ts`](src/utils/stats.ts)):

- **График по месяцам** — столбики трат за 12 месяцев со скользящим средним и
  разбивкой по категориям в подсказке;
- **Стоимость владения** — `Σ расходов за окно / число месяцев` и `/ пройденные км`.
  Отдельно показывается цифра **без платежей по кредиту** — именно так считают
  стоимость владения отраслевые исследования, поэтому сравнение честное:
  ориентир НАПИ для Granta Sport — 13,65 ₽/км и 204 800 ₽ в год
  ([autonews.ru](https://www.autonews.ru/news/66a25e829a794766bb61cf1f));
- **Прогноз на 12 месяцев** — платежи по кредиту (сколько их осталось) + топливо
  (`пробег за год / 100 · расход · цена литра`) + плановое ТО (работы из плана,
  которые подойдут за год, по средней вилке цены) + ОСАГО (факт за год или
  7 100 ₽) + транспортный налог.

## Транспортный налог

`Налог = мощность (л. с.) × ставка региона × месяцы владения / 12`
([`src/lib/tax.ts`](src/lib/tax.ts), ставки 2026 года для 7 регионов + базовая
ставка НК РФ; можно ввести свою). Мощность берётся из выбранного мотора
(Granta Sport 1.6 16V — 106 л. с.), срок уплаты — **1 декабря** следующего года,
карточка показывает сумму и сколько дней осталось.

## Экспорт данных

Вкладка «Моя Гранта» → «Мои данные» ([`src/lib/backup.ts`](src/lib/backup.ts)):

- **Резервная копия JSON** — авто, кредит, все расходы и журнал ТО одним файлом;
- **Расходы в CSV** и **Журнал ТО в CSV** — разделитель `;`, BOM и CRLF, чтобы
  Excel сразу открывал кириллицу и не ломал колонки.

Файлы формируются в браузере (`Blob` + `URL.createObjectURL`), ничего никуда не
отправляется. Имя — `lada-granta-ГГГГ-ММ-ДД.json` / `.csv`.

## Проверки

```bash
npm run typecheck          # типы
npm test                   # 51 модульный тест: аннуитет, досрочка, расход топлива,
                           #   план ТО, налог, статистика, CSV-экспорт, демо-бэкенд
npm run build              # tsc -b + vite build
node scripts/smoke-demo.mjs   # 14 проверок демо-режима в сборке с ключами Supabase
npm run smoke              # то же + SSR-рендер /auth, /, /credit, /expenses, /service, /garage
                           #   в трёх состояниях: с данными, пустой аккаунт, реальные контексты
SMOKE_DUMP=1 npm run smoke # дополнительно выгрузит текст экранов в node_modules/.tmp/dump/
npm run check              # типы + тесты + smoke + сборка одной командой
```

Браузера в CI нет, поэтому экраны проверяются серверным рендером (`react-dom/server`):
скрипт собирает приложение esbuild'ом, подставляет данные и падает, если любой
экран бросил исключение или отрендерил пустоту. Тесты лежат в
[`tests/unit.test.ts`](tests/unit.test.ts) и запускаются штатным `node --test`
(esbuild собирает их в CJS-бандл, поэтому TS-импорты работают без лоадеров).
