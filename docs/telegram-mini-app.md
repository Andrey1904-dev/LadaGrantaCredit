### Как это работает при запуске

1. Telegram открывает `WEB_APP_URL` и дописывает параметры запуска в hash: `#tgWebAppData=…&tgWebAppVersion=…`.
2. `bootstrapTelegramMiniApp()` видит `tgWebApp*` в URL (или сохранённые SDK параметры в
   `sessionStorage` при перезагрузке) и **только тогда** загружает
   `https://telegram.org/js/telegram-web-app.js`. Ждёт не дольше 3,5 с, потом сайт стартует без SDK.
3. Если среда подтверждена (`Telegram.WebApp` есть **и** `initData` не пустой или `platform ≠ unknown`),
   вызываются `expand()`, настройка цветов и viewport. Затем hash заменяется на маршрут
   HashRouter: `startapp` → `?screen=` → маршрут из hash → `/`.
4. Рендерится React; `TelegramMiniAppBridge` вызывает `ready()` после первого рендера,
   синхронизирует BackButton и после штатной проверки авторизации открывает раздел из deep link.

### Осознанные отступления от буквы ТЗ

- **SDK не подключается тегом `<script>` в `index.html`** (в ТЗ это «предпочтительно», а не обязательно).
  Скрипт `telegram-web-app.js` создаёт `Telegram.WebApp` в любом браузере, а синхронный скрипт
  с `telegram.org` задерживал бы отрисовку у всех посетителей сайта (и полностью блокировал бы её
  там, где `telegram.org` недоступен). Порядок загрузки при этом соблюдён: SDK исполняется
  раньше, чем HashRouter перепишет hash с параметрами запуска.
- **Одного наличия `window.Telegram?.WebApp` недостаточно** для определения среды (см. п. 3 выше) —
  иначе обычный браузер после загрузки SDK тоже считался бы Mini App. Это определение нужно
  только для интерфейса; для авторизации `initData`/`initDataUnsafe` не используются.
- **Раздел для кнопок бота передаётся параметром `?screen=<ключ>`**, а не hash `#/telegram`: Telegram
  передаёт параметры запуска в hash, а для кнопок `web_app` параметр `start_param` не поддерживается.
  `?screen=` проходит через тот же белый список, что и `startapp`, и выполняется только внутри Mini App.

| Проверка | Результат |
| --- | --- |
| Production URL | `https://andrey1904-dev.github.io/LadaGrantaCredit/` открывается, отдаёт экран входа (проверено 2026-09-30) |
| HTTPS | да, сертификат GitHub Pages (`*.github.io`) |
| Маршрутизация | `HashRouter`, `base: '/LadaGrantaCredit/'` — сохранены без изменений |
| Service Worker | отсутствует; `scripts/check-dist.mjs` падает, если в сборке появится `serviceWorker.register` |

| Произвольные HTTP-заголовки на GitHub Pages | **не настраиваются** — подтверждено GitHub: [community #54257](https://github.com/orgs/community/discussions/54257) |
| `X-Frame-Options` / CSP `frame-ancestors` | GitHub Pages по умолчанию их не отправляет → встраиванию в Telegram Web мешать не должны. **Из песочницы разработки снять заголовки не удалось** (исходящее TLS-соединение к `github.io` заблокировано), поэтому перед приёмкой выполните команду ниже |
| `Cache-Control` для `index.html` | GitHub Pages отдаёт свой (обычно `max-age=600`), изменить нельзя → новая версия может появиться в течение ~10 минут после деплоя. По ТЗ (3.3) это не блокирует; проверяется пунктом 12 матрицы |

Проверка заголовков (выполнить со своей машины):

```bash
curl -sI https://andrey1904-dev.github.io/LadaGrantaCredit/ | grep -iE 'x-frame-options|content-security-policy|cache-control'
```

- Пусто для `x-frame-options` и `content-security-policy` → хостинг менять не нужно.
- Если там есть `X-Frame-Options: DENY/SAMEORIGIN` или `frame-ancestors`, который не пускает Telegram
  Web, — это блокер хостинга (ТЗ 3.2): нужен CDN/прокси с управляемыми заголовками (например,
  Cloudflare перед Pages) или другой хостинг. Файлы вроде `_headers` в репозитории на GitHub Pages
  **не работают**.

## 3. Настройка

### 3.1 Переменные и секреты

| Переменная | Где хранится | Назначение |
| --- | --- | --- |
| `WEB_APP_URL` | секреты Supabase Edge Function, `bot/.env`, переменные окружения при запуске `bot:setup` | HTTPS-адрес сайта для кнопки меню и inline-кнопок. Hash отбрасывается |
| `TELEGRAM_BOT_TOKEN` | только серверные секреты (Supabase secrets, `bot/.env`, секреты хостинга/CI) | **никогда** не в `VITE_*`, коде, документации, логах |
| `SUPABASE_SERVICE_ROLE_KEY` | только серверные секреты | то же |

Новых переменных не добавлялось: Mini App использует существующую `WEB_APP_URL`.
`scripts/check-dist.mjs` проверяет, что в `dist/` нет токена бота, service-role/секретных ключей Supabase и вызовов `api.telegram.org/bot…`.

### 3.2 Кнопка меню и inline-кнопки

```bash
# полная настройка (webhook, описание, команды, кнопка меню Mini App)
TELEGRAM_BOT_TOKEN=… WEB_APP_URL=https://andrey1904-dev.github.io/LadaGrantaCredit/ \
  node scripts/telegram-bot-setup.mjs            # добавьте --deploy, чтобы заодно развернуть функцию

# только кнопка меню Mini App
TELEGRAM_BOT_TOKEN=… WEB_APP_URL=https://andrey1904-dev.github.io/LadaGrantaCredit/ npm run bot:menu
```

Скрипт выводит `Кнопка меню: «Кабинет» → Mini App <url>` после проверки через `getChatMenuButton`.
Команды бота (`/garage`, `/credit`, …) не удаляются — они доступны через «/» в поле ввода.

Inline-кнопки формирует ядро бота из `WEB_APP_URL` той среды, где работает бот (секреты Edge Function
или `bot/.env`). После смены `WEB_APP_URL` обновите секрет и передеплойте функцию (или перезапустите
Node-сервис). При пустом/HTTP-адресе кнопка кабинета просто не показывается, а кнопка меню
остаётся списком команд (Node-бот пишет предупреждение в лог).

> Node-сервис при каждом старте вызывает `applyBotProfile()` и тоже ставит кнопку меню `web_app`
> по своему `WEB_APP_URL` — держите одинаковый адрес в `bot/.env` и в секретах функции.

### 3.3 Прямая ссылка (желательно, настраивается в BotFather вручную)

Для запуска из других чатов:

1. @BotFather → `/mybots` → бот → **Bot Settings → Configure Mini App** → включить и указать
   `WEB_APP_URL` (Main Mini App). Либо `/newapp` для именованного приложения с `short_name`.
2. Ссылки:
   - Main Mini App: `https://t.me/<bot>?startapp=garage`
   - именованное: `https://t.me/<bot>/<short_name>?startapp=garage`
3. Допустимые ключи: `home`, `credit`, `expenses`, `service`, `garage`, `telegram` (+ синонимы
   `dashboard`, `spending`, `bot`). Неизвестный ключ открывает стартовый экран.

Эта регистрация скриптом не автоматизируется (ТЗ 5.3).

### 3.4 Тестовый бот

Для приёмки создайте отдельного бота в @BotFather и запустите скрипт с его токеном и тем же
production `WEB_APP_URL` (или адресом тестовой копии сайта на HTTPS). Для локальной отладки нужен
публичный HTTPS-адрес (например, туннель); `localhost` и HTTP скрипт отклоняет.

## 5. Известные ограничения

- Сессия Supabase хранится в `localStorage` WebView; она изолирована от мобильного браузера и
  может отличаться между клиентами Telegram — войти может понадобиться отдельно (ТЗ 6.1).
- Автоматический вход по Telegram (ТЗ 6.2) не реализован: сначала нужно согласовать способ
  привязки Telegram ID к аккаунту и выдачу сессии. Существующая привязка по одноразовому коду
  не выполняет вход на сайт.
- Сайт всегда в тёмной теме; под светлую тему Telegram перекрашивается только шапка/фон
  Mini App (в фирменный тёмный), а не весь интерфейс.
- На клиентах старше Bot API 6.9 цвет шапки не задаётся (они принимают только цвета темы
  Telegram — в светлой теме это была бы белая шапка над тёмным сайтом).
- `Cache-Control` на GitHub Pages изменить нельзя (см. раздел 2).
- Подтверждение «закрыть без сохранения» подключено к окну «Новый/редактировать расход»;
  остальные окна закрываются по «Назад» без вопроса (как и крестиком на сайте). Чтобы добавить
  подтверждение, передайте в `<Sheet>` проп `dirty`.
